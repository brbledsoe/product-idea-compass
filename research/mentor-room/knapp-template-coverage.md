## Foundation inventory in useful facilitation order

IDs below are this repository's reference IDs, not author-assigned numbering. The common decision pattern is independent writing, silent voting, then the actual Decider's choice. Vote allocations vary by activity; they express team judgment, not customer evidence. Brief discussion is allowed, with many frames discouraging more than five minutes of wordsmithing. Setup and method rationale remain in the [Click checklist reference](click-book-method.md#foundation-sprint-activity-inventory).

The scorecard's six founding-hypothesis questions concern customer, problem, approach, choice over competitors, differentiation, and whether the concept clicks. Its columns labeled customer votes hold **observers' judgments about each customer session**, not a customer voting exercise. The text encourages avoiding maybe; the visual legend nevertheless includes a yellow question mark alongside yes/no. Do not convert this pressure for a decision into fabricated certainty. Five columns are provided, with the fourth/fifth marked optional in this board version. There is no numerical rule that a particular count of green cells proves demand or viability.

## Differences and omissions the mandatory core must handle

Comparison is against the already reviewed [Click book method](click-book-method.md) and [official public-guide baseline](knapp-zeratsky-baseline.md), not against an unreviewed complete *Sprint* book.

| Finding | Integration consequence |
|---|---|
| The board adds a standalone Values exercise and explicit competitor-scale reality check. | Include their purpose in the core coverage checklist; prior principles/positioning can count only if they address these outputs. The board's below-4 heuristic is not measured competitive proof. |
| Classic differentiation has seven visible scales; Click includes Automation separately. | Retain Click's eight-category exploration, acknowledging this board variant; do not silently lose Automation. |
| Board options: 4–7. Click checklist: 3–7; its narrative also discusses narrowing when more than five remain. | Name the adopted variant and preserve meaningful alternatives. Do not present one universal author-prescribed count. |
| Values frame calls its selected output principles; mini-hypothesis instruction says two while placeholder says 2–3; summary instruction says one sentence while canvas allows one or two. | Treat these as local template inconsistencies. Preserve the substantive output, and state the chosen operational convention. |
| Goal and numeric Metrics are separate; map explicitly separates Discovery from Core; miniature hypotheses connect sketches to risks. | Preserve each output even if a shorter conversation combines them. A generic idea summary does not automatically satisfy all of them. |
| Board permits 3+ interviews under stated confidence conditions; the public five-day guide uses five. | Keep five as the public-guide default unless deliberately adopting the documented board variant. Fewer sessions need the board's recruiting justification; neither count establishes statistical market validation. |
| Board expands the six-question scorecard with mini hypotheses, target risks, session recaps, and a Decider conclusion. | Carry forward direct observations, contradictory evidence, interpretation, and uncertainty separately. Completed cells cannot substitute for real sessions. |
| Board makes recruit/screen/confirm, ownership, Hot Takes, next-week tasks, and hypothesis revision explicit. | Add these to completion/next-step checks; keep successive hypotheses and target-risk changes traceable. |
| This export does not provide the full preparation guide, complete interview script, prototype tool instructions, trial-run procedure, or comparative-customer-test rationale. | Supply these from the public guides and Click sources already cited in the baseline/book note. In particular, keep preparation, neutral five-part interviews, prototype trial, and actual competitor/status-quo comparison; do not infer them absent merely because they lack separate exported frames. |

The repeated 1–7 chart axes, extra blank rows, five-person Foundation writing areas, seven-person sketch areas, and example appointment slots are layouts. They do not independently override the team-size, experiment-quality, or selection instructions from the source methods.

## Proposed room implementation — synthesis and user requirements

These are proposed adaptations, not claims about what the authors prescribe for AI agents:

1. **One mandatory core with source coverage.** Maintain one artifact/check ledger for KTF/KTD outputs plus Click/public-guide-only requirements. Reuse a valid artifact across overlapping exercises, recording method, scope, source, gaps, and what was checked. Do not require duplicate boards for duplicate evidence.
2. **Solo facilitation stays honest.** The user can hold Decider authority. AI can help generate alternatives and critique them, but simulated independent mentors do not reproduce independent human expertise, team votes, or target customers. Preserve a silent-first user response before showing suggestions when independence matters; label agent proposals. Real expert input and real customer testing remain distinct activities.
3. **Adapt mechanics without claiming fidelity that was lost.** Solo alternatives can replace multiple human sketch submissions for exploration, while recording the changed setup. Prototype-count and scheduling choices must fit actual capacity. Use the cited sources when making an adaptation, and mark any missing method output rather than declaring it completed by conversation.
4. **Keep idea and component contexts explicit.** A hypothesis, differentiator chart, target map, or test belongs to a named customer/configuration. A promising component may become a separate candidate, but inherited evidence must be rechecked for its new context. Existing work receives credit only after that check.
5. **Decide the next investment, with a reason.** The board's build-or-learn prompts should produce a bounded next task, owner, and completion condition. Apply the case's own definition of worthwhile; a useful personal feature need not satisfy venture-scale growth. Preserve inconclusive, revise, park, and stop outcomes alongside pursue.

This inventory makes the saved board usable now without further uploads. It supports a first scoped skill and later testing, while leaving full-book/bonus/live-canvas coverage explicitly open.
