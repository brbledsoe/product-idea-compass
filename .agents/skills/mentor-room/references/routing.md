# Choose relevant sessions, account for the whole catalog

Read [catalog.json](catalog.json) once when starting a case, then revisit it when the audience, ambition, evidence, or investment stage changes. Its 49 rows preserve the user's original inventory; repeated authors, tools, interviews, and collections are separate resources, not 49 mandatory sessions.

For every row record selected, deferred, omitted, or covered with a **case-specific** reason. Examples of meaningful reasons: “sales-pitch work deferred until customer problem and alternatives are observed,” or “venture-scale screen omitted because this is a sole-user tool.” “Not relevant” alone is insufficient. Group equivalent reasons when explaining choices to the user; keep every row in the durable record. The initial unassessed values are not completed consideration.

The `routing_hint` values are catalog-based candidate uses, not verified claims about each source. `availability` distinguishes ready source notes from unacquired detailed material. Applying a supplied book does not mark a related unreceived podcast as read. `method_reference` identifies available substitutes explicitly; say which source was actually used.

## Working session choices

| Current uncertainty | First useful route | Relevant specialist candidates |
|---|---|---|
| Customer, problem, competing approaches | Mandatory Foundation core | Pincus discovery/variants; YC abridged interview/evaluation guidance |
| A bundle may contain a better smaller idea | Pincus atomic/MIS session | Pattern Breakers layers if enabling change matters |
| Whether anyone will take a concrete action | Savoia + Bland experiment contract | Walling for bootstrap investment bands; interview specialists to understand behavior |
| Which problem/solution to investigate next | Bland assumptions + core alternatives | Torres opportunity tree after real customer stories |
| Value versus usability versus ability to deliver | Core prototype/test + Bland risks | Cagan four-risk public framework |
| Plausible breakthrough/timing claim | Pattern Breakers | Hale/Currier when venture ambition makes them relevant |
| Target segment, differentiated value, sales commitment | Core differentiation and comparative tests | Dunford, Moesta, Abel; acquire specific material before detailed author-attributed facilitation |
| Existing users but uncertain repeat value | Pincus signal review, Bland behavior experiments | Vohra/Jackson and stage-specific PMF sources; real experienced users required |
| Next build/launch after evidence supports it | Bounded implementation/learning plan | Seibel, Misra, Walling, Fadell; not automatic production work |

For ready supplementary public practices, read [specialist methods](../../../../research/mentor-room/specialist-methods.md) only for the selected section. It includes Walling 5PM and 2/20/200, Torres, Cagan, and public Fitzpatrick guidance, with actual review limits. [Evidence and overlap](../../../../research/mentor-room/evidence-and-overlap.md) includes a bounded YC interview lens and Vohra's first-person PMF account. These do not constitute full books, courses, or podcast transcripts.

For an unavailable relevant method, perform a focused primary-source lookup and save an original, cited method note in `research/mentor-room/` with retrieval date, actual reviewed scope, locators, prerequisites, procedure, outputs, completion checks, limitations, and adaptations. Public read-only research is appropriate; no broad upload request, enrollment, purchase, or account signup is implied. If unavailable, state the gap and offer an available method for the same question without crediting it as that author's work. The resource audit is a historical access check, not a current promise of availability.

## Overlap and disagreement

- Foundation Basics, customer interviews, and a business/value map can share a customer/problem artifact only after checking each method's requirements. A generated persona stays a hypothesis.
- Savoia XYZ can be the hypothesis in a Bland Test Card. Pincus MIS can be its test object. One test stays one test; new mentor interpretations are not additional evidence.
- A realistic Design Sprint prototype can support usability and value learning. A signup pretotype cannot replace the required customer study, technical feasibility work, or repeat-use evidence.
- Pincus preserves proven mechanics while Pattern Breakers examines breakthrough distinctiveness. Apply their claims at the relevant level, and do not impose radical novelty on every feature.
- Knapp–Zeratsky money/growth lenses compare approaches even for small ideas. Adapt their labels to personal value, reach, effort, and maintenance where appropriate, recording the change. Walling's bootstrap criteria and Hale's venture criteria reflect different ambitions.
- PMF diagnostics require actual experience. Surveying hypothetical users about missing an imaginary product does not establish product-market fit.
- When sources disagree about a count or sequence, name the selected version and preserve the alternate in the source note. Do not average source heuristics into an invented validation score.

Reading a source is not performing its exercises; performing an exercise is not observing customers; observing one behavior does not prove every claim. Keep these distinctions visible in coverage and recommendations.
